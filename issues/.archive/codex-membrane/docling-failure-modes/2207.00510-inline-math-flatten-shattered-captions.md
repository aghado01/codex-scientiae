# Docling PDF Extraction Failure Modes

**Specimen:** `2207.00510` (Title: *Enhancing cluster analysis via topological manifold learning*)
**Run Metadata (Membrane/Docling):** `.runs/20260702_142012`
**Comparison Baseline (LaTeX):** `2207.00510-latex.md` (source unpacked at `.runs/20260702_144604/tex/`)

This document serves as a detailed post-mortem and analysis of the failure modes exhibited by the Docling-based PDF extraction pipeline, using the aforementioned specimen as a case study. Cross-examination with the original LaTeX source code reveals several fundamental limitations of visual-layout-based (OCR/PDF) extraction when applied to complex academic layouts rich in mathematics and figures.

## 1. Shattered Layouts and Floating Elements

### Phenomenon
Docling struggles to distinguish between main body prose and the text of floating elements like figure legends or footnotes when they visually interrupt the main column of text. 

### Observation
In the specimen run, figure captions were completely "shattered" from their figures and transcribed as raw body paragraphs. 
For example, the text: 
> `"Fig. 1 ARI and NMI as a function of \varepsilon for the synthetic settings E 100 , E 1000 , U 3 , U 1003 ..."` 

was injected directly into the middle of the prose flow, disrupting semantic continuity. 

### Impact
Because the text is misclassified as standard prose (`is_furniture = $false`), downstream membrane tools (like `finalize.ps1`) do not flag it for removal or formatting. This results in jarring reading experiences and pollutes the token stream for LLM ingestion.

## 2. Severe Inline-Math Degradation

### Phenomenon
Docling preserves **display** math as structured LaTeX (routed through its formula recognizer) but flattens **inline** math to plain Unicode text, discarding all typographic structure — subscript/superscript position *and* glyph diacritics such as the slash of `≠`. The Membrane codebase already documents exactly this split (`normalize.ps1`: *"docling keeps DISPLAY math as structured LaTeX but flattens INLINE math to text"*). It is therefore **not** a general pixel-level OCR loss — the display equations round-trip perfectly — but a structural downgrade confined to the inline-math stream.

### Observation
Cross-examination against the LaTeX source shows a **single root cause** (inline flattening) with two symptoms:
- **Subscript/superscript collapse (inline only).** Docling extracted `$\sigma_i$` as `σ i` and `$\rho_i$` as `ρ i` — base and script split into two space-separated tokens. The *same symbols survive intact in display math* (`\sigma_{i}`, `\rho_{i}`, `x_{i_{j}}`), which is exactly why the Membrane's Rosetta-Stone pass (§4.1) can partially rebuild them from the display vocabulary.
- **Diacritic drop → operator inversion.** The inequality `\neq` flattened to `=`. The LaTeX source reads `$d(x_i, x_j) \neq d(x_i, x_j)$` and Docling emitted `d ( x_i ,x_j ) = d ( x_i ,x_j )` — the operands are preserved; only the slash of `≠` is lost, silently turning *"not equal"* into *"equal."*
  - **Correction to an earlier draft of this note:** the source RHS is `d(x_i, x_j)`, **not** `d(x_j, x_i)`. The paper itself carries an authorial typo (both sides identical, where the sentence's logic about directional asymmetry clearly intends `d(x_j, x_i)`). Docling neither introduced nor repaired that typo — the *only* corruption Docling caused is `≠ → =`. Reporting the swapped-index form as the source would be attributing a silent "correction" to the extractor that never happened.

A third symptom belongs to **display** math, and is a different mechanism from the inline flattening above:
- **Detached equation numbers.** Floating numbers (e.g. `(3)`) hang at the right margin and were extracted as disconnected chunks (`& & ( 3 )` — the alignment ampersands plus a stray tag) rather than folded into the math block via `\tag{3}`.

### Impact
The inline-flattening class is the most dangerous failure mode: it is silent, meaning-changing (`≠ → =` literally inverts a claim), and — unlike shattered furniture — unrecoverable by an agent from the flattened text alone. Structural furniture can be cleaned post-hoc; a flipped operator cannot. Display-math fidelity, by contrast, is largely intact and is not the concern here.

## 3. Loss of Semantic Environments

### Phenomenon
Academic papers often use specific LaTeX environments (e.g., `\begin{theorem}`, `\begin{definition}`) to structure logical arguments. Visually, these just look like indented or bolded text.

### Observation
Docling extracted these blocks merely as plain text (e.g., `"Definition 1 The distance $\rho i$... "`), entirely losing the semantic metadata that would normally allow us to wrap them in markdown bolding or blockquotes. 

### Impact
The resulting markdown loses the academic structure intended by the authors, reducing the scannability and structural rigor of the corpus.

## 4. Membrane Workflow vs. Docling Direct Markdown

As part of this analysis, we also cross-examined the output of the Membrane ingestion workflow (`2207.00510-membrane.md`) against Docling's native direct Markdown export (`2207.00510.md`) to identify gaps and workflow insights.

### 4.1 Inline Math Recovery (Membrane's Strength)
- **Docling Direct MD:** Flattens inline math completely into plain Unicode text without any delimiters. For instance, $\sigma_i$ is output merely as `σ i` amidst regular prose.
- **Membrane Workflow:** The Membrane's `normalize.ps1` script runs a "Rosetta Stone" pass—it learns subscript/superscript patterns from the preserved Display Math and attempts to reconstruct flattened inline variables. While it couldn't fully rebuild `\sigma_i` (falling back to `$\sigma i$`), it successfully wrapped it in math delimiters (`$ $`), preserving its semantic identity as a mathematical variable.

### 4.2 The "Shattered Caption" Regex Failure
- Why did figure captions leak into the Membrane body text? The Docling JSON IR explicitly classified the figure caption ("Fig. 1 ARI and NMI...") as a `paragraph`. 
- To counteract this, Membrane uses `Get-FurnitureKind` in `normalize.ps1` to detect captions via the regex: `'^(Figure|Fig\.?|Table|Tab\.?)\s*\d+\s*[:.]'`.
- **The Failure:** This regex strictly demands a colon or period after the figure number (`[:.]`). Because this specific document formats captions as `"Fig. 1 ARI..."` (with a space, no colon/period), the regex failed to flag it as `is_furniture = 'caption'`, allowing it to pollute the prose.

### 4.3 Unleveraged Metadata in JSON IR
- An inspection of the Docling JSON IR reveals that it perfectly captured the font size differences: body text was `9.963` pt (`CMR10`), while the figure caption was `7.97` pt (`CMR8`).
- **The Gap:** Docling's direct Markdown engine discards this metadata entirely. The Membrane *does* consume font signals elsewhere — `headings.ps1` uses a `font != null` promoter gate, and the pdfdig lane carries a `font-roles.jsonl` store — but neither leverages **font size** for *caption/footnote* classification in `normalize.ps1`. Closing that specific gap is the opportunity here.

## 5. Conclusion & Strategic Recommendations

The failure modes observed in run `20260702_142012` highlight that **PDF-based extraction pipelines like Docling are poorly suited as the primary ingestion mechanism for math-heavy literature.** The errors produced—such as dropping subscripts and flipping inequality operators—are silent, highly destructive, and exceptionally difficult for an LLM agent to detect and repair post-hoc without the original source code. 

### Recommendation 1: Prioritize and Harden LaTeX Ingestion (When Available)
The pipeline should pivot to prioritize the source-compiled LaTeX extraction (`latex-ingest.ps1`) as the primary driver for text and math. To make it promotion-worthy:
- **Fix Nested Brace Extraction:** Upgrade `latex-ingest.ps1` to use a true brace-matching algorithm (or recursive regex) instead of `[^{}]*` for extracting `\caption`, `\footnote`, and other nested commands.
- **Implement Figure/Table Counters:** Extend the `Build-LabelMaps` function to track `\begin{figure}` and `\begin{table}` so that `\ref{fig:..}` resolves accurately to `Figure 1`, `Figure 2`, etc.
- **Handle Inline Furniture:** Add passes to convert `\verb|...|` into Markdown inline code `` `...` ``, and strip orphaned `\\` linebreaks from prose.

### Recommendation 2: Improve the Membrane Workflow (When LaTeX is Unavailable)
Since a LaTeX oracle won't always be available, the Docling-based Membrane workflow must be made more robust against visual-layout anomalies:
- **Relax Furniture Regexes:** Update `Get-FurnitureKind` in `normalize.ps1` to make the colon/period optional (`[:.]?`), ensuring it catches formats like `"Fig. 1 Text"`.
- **Leverage Font Size Heuristics:** Upgrade `preprocess.ps1` or `normalize.ps1` to dynamically compute the median body font size. If a "paragraph" node is significantly smaller (e.g., `< 85%` of the median), it should be strongly considered for classification as a caption, footnote, or `crumb`, preventing it from polluting the main prose stream.
