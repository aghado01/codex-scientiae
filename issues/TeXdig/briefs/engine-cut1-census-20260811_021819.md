# TeXdig census engine — cut 1 implementation brief (20260811_021819)

Consolidates the stage-1 design sessions of 2026-08-10/11 into the build plan for the engine's
first implementation. Normative spec: [src/TeXdig/README.md](../../../src/TeXdig/README.md),
[core/types.ts](../../../src/TeXdig/core/types.ts), [core/contracts.ts](../../../src/TeXdig/core/contracts.ts).
Companion: the agy cross-examination findings brief (sibling file), whose accepted items are already
encoded in the spec.

## Objective

The census substrate: two-witness census + pillar claims + coverage/residue + diagnostics over the
**complete source** (LaTeX and `.bbl` via unified-latex, `.bib` via latex-utensils), emitting the
**evidence tier** (`sources.jsonl`, `entities.jsonl`, `claims.jsonl`) and **audit tier**
(`coverage.json`, `diagnostics.jsonl`, `summary.json`) per the landed contract. Contract-tier
stores (walk/zones/macros/references/pointers/frontmatter/graph) are cuts 2–3; `summary.json`
declares which stores this cut emits so absence is a statement, not an accident.

## Input contract

- One deposited article dir per run: `article.json` (lightweight `validate-json` shape check only —
  deposit owns validation), `{slug}-tex/` strictly read-only; run attributed by tree `sha256` +
  schema versions + runstamp.
- First light: **one ph-zigzag gauntlet slug, one at a time** (user directive); ramp to batches only
  after stage 1 is stable. `ingestion/inventory` is the easy-mode fallback.

## Architecture (src/TeXdig/)

- `core/` — types.ts, contracts.ts (landed; the fixed target).
- `census/` — modules in pipeline order:
  1. `stratify.ts` — comment/verbatim stratification. Runs before EVERYTHING, including the
     include graph (commented `\input` of a nonexistent file exists in the corpus).
  2. `source-graph.ts` — include/resource graph over stratified text; role classification
     (types.ts `SourceRole`); case-mismatch canonicalization (on-disk casing wins + diagnostic);
     unreachable-tex diagnostics.
  3. `scan-latex.ts` / `scan-bib.ts` — lexical witnesses: complete positions, shallow typing.
  4. `parse-latex.ts` / `parse-bib.ts` — parser witnesses behind an explicit-`depsRoot` loader
     (`--deps <repo>/packages/node/node_modules`; dynamic ESM import of flat package entries;
     no ambient resolution). Two-pass parse for LaTeX: discover definitions → signature registry →
     reparse. Configured signatures (theorem envs from unparsed classes) enter as
     `configured`-dialect entities.
  5. `reconcile.ts` — witness fusion: agreement states, hull synthesis for parser position gaps
     (synthesized spans marked), all census entity kinds incl. bib entities and
     environment-definitions.
  6. `claims.ts` — pillar overlays (envelope/spine/fence; spine claims POSITIVE, never
     complement).
  7. `coverage.ts` — per-parsed-source accounting; residue spans; gate 1+2 computation.
  8. `emit.ts` — JSONL emission: UTF-8 no BOM, LF, ids per the `{class}:{locator}` grammar,
     inline slices on entity rows.
- `cli/census.ts` — entry: `node census.ts --article <dir> --deps <dir> --out <container>`.
  Direct-CLI runs emit to `artifacts/texdig-runs/{stamp}/{slug}/`; the batch-executor container
  address takes over when the adapter lands.

## Constraints (standing doctrine)

- Erasable-syntax TS only, Node 26 native stripping, explicit `.ts` import extensions, no new deps.
- Source slices always from the raw stream; `printRaw` never used for content.
- Diagnostic codes from the registered const only; csnames byte-exact case-sensitive.
- No magic-string structural heuristics; small-vocabulary classification with `generic` fallback.
- Witness records carry `instrument`; nothing asserts without provenance.

## Exit criteria (cut 1 done)

1. First-light run on the chosen ph-zigzag slug completes; all six stores emitted; summary reports
   gates 1–2 (they need not PASS — residue and disagreements are findings, and their honest
   reporting is the point).
2. Pester coverage: a committed mini-fixture tree under `tests/fixtures/texdig/` exercises
   stratify-ordering (commented include), hull synthesis, bib census, and case-mismatch; store
   shapes asserted against the DTO layer.
3. Coverage and agreement numbers from first light reviewed with the user before cut 2 scope is
   set (the residue profile directs the joins work).

## Sequencing after cut 1

PS worker (`validate-json` + census invocation) → `Get-TeXdigBatchJob` in batch-adapters (one
document per job) → cut 2 relation joins (binding incl. bound-out-of-scope, attachment, support
closure, purity) → cut 3 zones/walk compilation, isolated evaluation, render + differential
validation. Schema promotion to the jsonl_engine registry only after battle-testing (DTO layer
iterates freely until then).

## Report

**20260812 — Gemini first cut, cross-examination, and rebuild.**

Gemini's implementation (plan: [gemini-cut1-implementation-plan.md](gemini-cut1-implementation-plan.md))
landed the full module skeleton, correct span arithmetic, the unified-latex/latex-utensils
integration, and the six stores — but the central mechanism was scaffolding: `reconcile.ts` minted
every entity from one witness with `agreement: "agreed"` hard-coded (gate 2 vacuous), the lexical
witness's output was discarded, the include graph never reached the artifact (`targetRaw: ""`),
both witnesses ran on RAW text (stratification not honored downstream of the include graph), and
definition discovery covered only the newcommand family + newtheorem. Confirmed bugs: shared regex
`lastIndex` across include recursion (duplicate edges/diagnostics), `\bibitem` hull swallowing
whole bibliography items (implicit item-body args), silent no-op on missing entrypoint, and a
`main.tex` entrypoint guess.

Rebuild (same session, Claude): real witness fusion with computed agreement states and
per-disagreement diagnostics; both witnesses consume stratified text; document-global signature
registry (pass-1 discovery across all parsed files, pass-2 reparse); definition dialects extended
to def/gdef/edef/xdef, let, DeclareMathOperator, DeclarePairedDelimiter, xparse family,
newenvironment, newfloat (with `elaborable` flags); hulls gated to bracketed args only; include
entities carry targetRaw + resolvedSourceId (per-target spans for comma lists; `\bibliography` is
BOTH include and envelope-marker); scanner sights `^`/`_` and steps into math interiors; new
registered codes EntrypointMissing, LatexParseError, TreeManifestMismatch; UnterminatedMath/
UnterminatedVerbatim/UnmatchedBegin/UnmatchedEnd now emitted; summary declares emitted vs deferred
stores; parser spans validated against the positioned ancestor chain (unified-latex reparses
alignment environments like `cases` in a LOCAL coordinate frame — untrusted spans drop to the
lexical witness at true offsets).

**First light (2111.15058v3)**: 5547 entities, agreement 5527 agreed / 20 lexical-only (all in
corrupted `cases` frames, honestly attributed) / 0 parser-only; coverage 105082/105140 UTF-16
(residue ≈ EOF newlines + cases interiors); 0 duplicate ids; 1 defect — the deposit tree was
MODIFIED after deposit (manifest says 14 files, tree holds 7; nested duplicate directory removed
without re-deposit), caught by the new TreeManifestMismatch guard. Pester: 22/22.

Open design questions (user's surface, discussion pending): macro-invocation pillar assignment
(currently `envelope` catch-all), bib/bbl parse-reachability policy (currently parse-all by
extension), configured-dialect signature channel (unimplemented — needs a lane-config surface),
UnknownEnvironment/OpaqueRegion codes still unemitted (cut-2 binding territory).
