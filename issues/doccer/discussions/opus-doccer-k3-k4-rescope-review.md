**Two things the code already settles.**

_The basis seam D33 needs is landed law._ Occurrence-bearing carriers use reference identity on the frozen batch — `ClaimSelection` ([:171](src/doccer/Algebra/ClaimSelection.cs:171), [:224](src/doccer/Algebra/ClaimSelection.cs:224)), `ClaimPairView` ([:351](src/doccer/Algebra/ClaimPairView.cs:351)), `Pairing` ([:248](src/doccer/Algebra/Pairing.cs:248)) — and reach for `EnsureCompatibleWith` only on the _master_, when crossing between two batches ([ClaimPairView.cs:421](src/doccer/Algebra/ClaimPairView.cs:421)). The identity-forgetting carrier uses value compatibility instead: `SpanSet.Equals` goes through `IsCompatibleWith` and hashes DocumentId+Revision+Fingerprint ([:179](src/doccer/Algebra/SpanSet.cs:179), [:200](src/doccer/Algebra/SpanSet.cs:200)). So `CandidateRegionGraph` inherits reference-strictness through `ClaimSelection` and `LocatedRelation` inherits fingerprint-compatibility through the `SpanSet` precedent — the projection _is_ the hop across that seam. No open question, but the brief says "compatible masters and exactly equal windows" for located ops without noting the graph side is strictly stricter.

_My ordinal flag is weaker than I put it._ Raw insertion-order ordinal is already the landed final tie-break: `Laminarizer` sorts to `FirstOrdinal` ([:67](src/doccer/Algebra/LaminarView.cs:67)), and `ClaimOrdering.Compare` ends at ordinal precisely to be total ([SpanBatch.cs:342](src/doccer/Core/SpanBatch.cs:342)). `FirstOrdinalCompletePath` is consistent with D2/D24 practice, not a novelty — worth one sentence in the contract, not adjudication.

**Two things the code exposes.**

_`Laminarizer` is the only site in `Algebra/` that never got selection-backed._ Suppression, GapCadence, Grouping, and `SpanSet.FromClaims` all route through `ClaimSelection`; `LaminarView.cs` contains zero references to it and filters with raw LINQ ([:61](src/doccer/Algebra/LaminarView.cs:61)). It also carries no basis stamp — no `Batch`, no `Master`, no policy object — so an empty `LaminarView` cannot answer D21's "over what was I computed," and the greedy order is hard-coded with nothing recording it. Three landed disciplines (D2 policy stamps, D21 basis stamps, D30 selection-backing) that it predates.

_There is no `Meets` predicate._ `TextSpan` has Contains / ProperlyContains / Intersects / Crosses. Shared-boundary `Seq` and `PartitionView`'s meeting adjacency both need `left.End == right.Start`, and `Intersects` deliberately cannot express it (D17 — adjacent spans don't intersect, empty spans intersect nothing). Small, but it's a core-chip surface decision.

Those two exposures converge on my DAG item: the Laminarizer's debt is D21/D30 hygiene, not selection semantics — which is evidence that K4c depends on K4a and the hygiene backlog, and doesn't need K4b's objective contract at all.
