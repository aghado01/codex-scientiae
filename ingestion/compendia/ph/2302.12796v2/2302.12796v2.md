# Abstract

It is well known that ordinary persistence on graphs can be computed more eﬃciently than the general persistence. Recently, it has been shown that zigzag persistence on graphs also exhibits similar behavior. Motivated by these results, we revisit graph persistence and propose eﬃcient algorithms especially for local updates on ﬁltrations, similar to what is done in ordinary persistence for computing the vineyard . We show that, for a ﬁltration of length m , (i) switches (transpositions) in ordinary graph persistence can be done in O (log m ) time; (ii) zigzag persistence on graphs can be computed in O ( m log m ) time, which improves a recent O ( m log 4 n ) time algorithm assuming n , the size of the union of all graphs in the ﬁltration, satisﬁes n ∈ Ω( m ε ) for any ﬁxed 0 < ε < 1; (iii) open-closed, closed-open, and closed-closed bars in dimension 0 for graph zigzag persistence can be updated in O (log m ) time, whereas the open-open bars in dimension 0 and closed-closed bars in dimension 1 can be done in O ( √ m log m ) time.

Computing persistence for graphs has been a special focus within topological data analysis (TDA) [9, 10] because graphs are abundant in applications and they admit more eﬃcient algorithms than general simplicial complexes. It is well known that the persistence algorithm on a graph ﬁltration with m additions can be implemented with a simple Union-Find data structure in O ( mα ( m )) time, where α ( m ) is the inverse Ackermann’s function (see e.g. [9]). On the other hand, the general-purpose persistence algorithm on a simplicial ﬁltration comprising m simplices runs in O ( m ω ) time [18], where ω < 2 . 373 is the exponent for matrix multiplication. In a similar vein, Yan et al. [21] have recently shown that extended persistence [4] for graphs can also be computed more eﬃciently in O ( m 2 ) time. The zigzag version [2] of the problem also exhibits similar behavior; see e.g. the survey [1]. Even though the general-purpose zigzag persistence algorithm runs in O ( m ω ) time on a zigzag ﬁltration with m additions and deletions [3, 8, 17, 18], a recent result in [6] shows that graph zigzag persistence can be computed in O ( m log 4 n ) time using some appropriate dynamic data structures [14, 16] ( n is the size of the union of all graphs in the ﬁltration).

Motivated by the above developments, we embark on revisiting the graph persistence and ﬁnd more eﬃcient algorithms using appropriate dynamic data structures, especially in the dynamic settings [5, 7]. In a dynamic setting, the graph ﬁltration changes, and we are required to update the barcode (persistence diagram) accordingly. For general simplicial complexes as input, the vineyard algorithm of [5] updates the barcode in O ( m ) time for a switch of two consecutive simplices (originally called a transposition in [5]). So, we ask if a similar update can be done more eﬃciently for a graph ﬁltration. We show that, using some appropriate dynamic data structures, indeed we can execute such updates more eﬃciently. Speciﬁcally, we show the following:

- 1. In a standard (non-zigzag) graph ﬁltration comprising m additions, a switch can be implemented in O (log m ) time with a preprocessing time of O ( m log m ). See Section 3. As a subroutine of the update algorithm for switches on graph ﬁltrations, we propose an update on the merge trees (termed as merge forest in this paper) of the ﬁltrations, whose complexity is also O (log m ).
- 2. The barcode of a graph zigzag ﬁltration comprising m additions and deletions can be computed in O ( m log m ) time. Assuming n ∈ Ω( m ε ) for any ﬁxed positive ε < 1, where n is the size of the union of all graphs in the ﬁltration, this is an improvement over the O ( m log 4 n ) complexity of the algorithm in [6]. See Section 4. Also, our current algorithm using Link-Cut tree [20] is much easier to implement than the algorithm in [6] using the Dynamic Minimum Spanning Forest [16].
- 3. For switches [7] on graph zigzag persistence, the closed-closed intervals in dimension 0 can be maintained in O (1) time; the closed-open and open-closed intervals, which appear only in dimension 0, can be maintained in O (log m ) time; the open-open intervals in dimension 0 and closed-closed intervals in dimension 1 can be maintained in O ( √ m log m ) time. All these can be done with an O ( m 1 . 5 log m ) preprocessing time. See Section 5.


# 2 Preliminaries

Graph zigzag persistence. A graph zigzag ﬁltration is a sequence of graphs

$$
\mathcal { F } \colon G _ { 0 } \leftrightarrow G _ { 1 } \leftrightarrow \cdots \leftrightarrow G _ { m } ,
$$

in which each G i ↔ G i +1 is either a forward inclusion G i ↪ → G i +1 or a backward inclusion G i ← ↩ G i +1 . For computation, we only consider simplex-wise fi ltrations starting and ending with empty graphs in this paper, i.e., G 0 = G m = ∅ and each inclusion G i ↔ G i +1 is an addition or deletion of a single vertex or edge (both called a simplex ). Such an inclusion is sometimes denoted as G i σ ← → G i +1 with σ indicating the vertex or edge being added or deleted. The p -th homology functor ( p = 0 , 1) applied on F induces a zigzag module :

[Page 3]

$$
H _ { p } ( \mathcal { F } ) \colon H _ { p } ( G _ { 0 } ) \leftrightarrow H _ { p } ( G _ { 1 } ) \leftrightarrow \cdots \leftrightarrow H _ { p } ( G _ { m } ) ,
$$

in which each H p ( G i ) ↔ H p ( G i +1 ) is a linear map induced by inclusion. It is known [2, 13] that H p ( F ) has a decomposition of the form H p ( F )     k ∈ Λ I [ b k ,d k ] , in which each I [ b k ,d k ] is an interval module over the interval [ b k ,d k ]. The multiset of intervals Pers p ( F ) := { [ b k ,d k ] | k ∈ Λ } is an invariant of F and is called the p -th barcode of F . Each interval in Pers p ( F ) is called a p -th persistence interval and is also said to be in dimension p . Frequently in this paper, we consider the barcode of F in all dimensions Pers ∗ ( F ) :=   p =0 , 1 Pers p ( F ).

Standard persistence and simplex pairing. If all inclusions in Equation (1) are forward, we have a standard ( non-zigzag ) graph ﬁltration. We also only consider standard graph ﬁltrations that are simplex-wise and start with empty graphs. Let F be such a ﬁltration. It is well-known [11] that Pers ∗ ( F ) is generated from a pairing of simplices in F s.t. for each pair ( σ,τ ) generating a [ b,d ) ∈ Pers ∗ ( F ), the simplex σ creating [ b,d ) is called positive and τ destroying [ b,d ) is called negative . Notice that d may equal ∞ for a [ b,d ) ∈ Pers ∗ ( F ), in which case [ b,d ) is generated by an unpaired positive simplex. For a simplex σ added from G i to G i +1 in F , we let its index be i and denote it as idx F ( σ ) := i . For another simplex τ added in F , if idx F ( σ ) < idx F ( τ ), we say that σ is older than τ and τ is younger than σ .

Merge forest. Merge forests (more commonly called merge trees) encode the evolution of connected components in a standard graph ﬁltration [10, 19]. We adopt merge forests as central constructs in our update algorithm for standard graph persistence (Algorithm 1). We rephrase its deﬁnition below:

Deﬁnition 1 (Merge forest) . For a simplex-wise standard graph ﬁltration

$$
\mathcal { F } \colon \varnothing = G _ { 0 } \stackrel { \sigma _ { 0 } } { \longrightarrow } G _ { 1 } \stackrel { \sigma _ { 1 } } { \longrightarrow } \dots \dots \stackrel { \sigma _ { m - 1 } } { \longrightarrow } G _ { m } ,
$$

its merge forest MF ( F ) is a forest (acyclic undirected graph) where the leaves correspond to vertices in F and the internal nodes correspond to negative edges in F . Moreover, each node in MF ( F ) is associated with a level which is the index of its corresponding simplex in F . Let MF i ( F ) be the subgraph of MF ( F ) induced by nodes at levels less than i . Notice that trees in MF i ( F ) bijectively correspond to connected components in G i . We then constructively deﬁne MF i +1 ( F ) from MF i ( F ), starting with MF 0 ( F ) = ∅ and ending with MF m ( F ) = MF ( F ). Speciﬁcally, for each i = 0 , 1 ,...,m − 1, do the following:

σ i is a vertex: MF i +1 ( F ) equals MF i ( F ) union an isolated leaf at level i corresponding to σ i .

σ i is a positive edge: Set MF i +1 ( F ) = MF i ( F ).

σ i is a negative edge: Let σ i = ( u,v ). Since u and v are in diﬀerent connected components C 1 and C 2 in G i , let T 1 ,T 2 be the trees in MF i ( F ) corresponding to C 1 ,C 2 respectively. To form MF i +1 ( F ), we add an internal node at level i (corresponding to σ i ) to MF i ( F ) whose children are the roots of T 1 and T 2 .

In this paper, we do not diﬀerentiate a vertex or edge in F and its corresponding node in MF ( F ).

\mathcal { F } \colon \varnothing & = G _ { 0 } \hookrightarrow \dots \hookrightarrow G _ { i - 1 } \overset { \sigma } { \hookrightarrow } G _ { i } \hookrightarrow G _ { i + 1 } \hookrightarrow \dots \hookrightarrow G _ { m } \overset { \tau } { \hookrightarrow } \\ \mathcal { F } ^ { \prime } \colon \varnothing & = G _ { 0 } \hookrightarrow \dots \hookrightarrow G _ { i - 1 } \overset { \tau } { \hookrightarrow } G _ { i } ^ { \prime } \overset { \sigma } { \hookrightarrow } G _ { i + 1 } \hookrightarrow \dots \hookrightarrow G _ { m } \overset { \ell ^ { \prime } } { \hookrightarrow }
$$

In the above operation, the addition of two simplices σ and τ are switched from F to F   . We also require that σ  ⊆ τ [5] ( σ is not a vertex of the edge τ ) because otherwise G   i is not a valid graph.

For a better presentation, we provide the idea at a high level for the updates in Algorithm 1; the full details are presented in Algorithm 2 in Section 3.1.

We also notice the following fact about the change on pairing caused by the switch in Equation (2) when σ,τ are both positive or both negative. Let σ be paired with σ   and τ be paired with τ   in F . (If σ or τ are unpaired , then let σ   or τ   be null .) By the update algorithm for general complexes [5], either (i) the pairing for F and F   stays the same, or (ii) the only diﬀerence on the pairing is that σ is paired with τ   and τ is paired with σ   in F   .

Data structure for merge forests. We use the Depth First Tour Tree (DFT-Tree) proposed by Farina and Laura [12] to implement the merge forest T , which supports the following operations:

- • root ( v ): Returns the root of the tree containing node v .
- • cut ( v ): Deletes the edge connecting node v to its parent.
- • link ( u,v ): Makes the root of the tree containing node v be a child of node u .
- • nca ( u,v ): Returns the nearest common ancestor of two nodes u,v in the same tree.
- • change-val ( v,x ): Assigns the value associated to a leaf v to be x .
- • subtree-min ( v ): Returns the leaf with the minimum associated value in the subtree rooted at v .


Let N be the number of nodes. All above operations in DFT-Tree take O (log N ) time. Among the operations, root is used to determine whether two nodes in T are from the same tree; cut and link are used to make the structural changes as in Figure 3; change-val is used to record (and update during switches) the levels of leaves; subtree-min is used to return the leaf at the lowest level in a subtree.

Detecting cycles. Algorithm 1 needs to check whether the edge e 1 resides in a 1-cycle in G i +1 (see the edge-edge switch). We show how to check this by dynamically maintaining a minimum spanning forest (MSF) for G := G m using the Link-Cut tree [20] in O (log m ) time per switch. First, let the weight of each edge e of G be the index of e in F , i.e., if e is added to a graph G j in F , then w ( e ) = j . Moreover, for a path in a graph, deﬁne its bottleneck weight as the maximum weight of edges on the path. By representing the MSF of G as a Link-Cut tree, we use the following procedure to check whether e 1 resides in a 1-cycle in G i +1 when switching two edges e 1 ,e 2 with e 1 negative and e 2 positive:

[Page 7]

- 1. Let e 2 = ( u,v ). Retrieve the bottleneck weight w ∞ of the path connecting u,v in the MSF of G . This can be done in O (log m ) time using the Link-Cut tree.
- 2. If w ∞ equals i − 1 (which is the weight of e 1 ), then e 1 is in a 1-cycle in G i +1 ; otherwise, e 1 is not in a 1-cycle in G i +1 .


To see the correctness of the above procedure, ﬁrst consider the case that e 1 is in a 1-cycle in G i +1 . We must have that e 1 ,e 2 connect to the same two components as shown in Figure 2 (see the proof of Proposition 7). Consider running the Kruskal’s algorithm on the sequence of edges in F : It must be true that u,v ﬁrst become connected after e 1 is added to the partial MSF maintained by the Kruskal’s algorithm. Therefore, the bottleneck weight of the path connecting u,v in the MSF of G equals i − 1 which is the weight of e 1 . Now consider the case that e 1 is not in a 1-cycle in G i +1 . The addition of e 2 creates a 1-cycle in G   i because e 2 is positive in F   . So we have that u,v are already connected in G i − 1 . Consider running the Kruskal’s algorithm on the sequence of edges in F . Before adding e 1 to the partial MSF in Kruskal’s algorithm, u,v are already connected by a path in the partial MSF. Therefore, the bottleneck weight of the path connecting u,v in the MSF of G must be less than i − 1.

For the switch from F to F   , we also need to update the MSF of G due to the weight change on certain edges. We ﬁrst notice that switching a vertex and an edge does not change the structure of the MSF and the update is easy. For a switch of two edges e 1 ,e 2 , we do the following in the diﬀerent cases:

e 1 ,e 2 are both positive: After the switch, e 1 and e 2 are still positive. Since only negative edges appear in the MSF of G (see, e.g., the Kruskal’s algorithm), they are not in the MSF of G before and after the switch and therefore the MSF stays the same.

e 1 is positive and e 2 is negative: Based on Proposition 7 in Section 3.1.4, e 1 stays positive and e 2 stays negative after the switch. Therefore, the fact that e 1 is not in the MSF and e 2 is in the MSF does not change before and after the switch. So we have that the structure of the MSF stays the same. Notice that due to the switch, the weight of e 1 in the MSF changes, whose update can be done by cutting e 1 ﬁrst and then re-linking it.

e 1 ,e 2 are both negative: After the switch, e 1 and e 2 are still negative. The structure of the MSF stays the same because e 1 ,e 2 are both in the MSF before and after the switch. Notice that we also need to update the weights for the two edges in the Link-Cut tree as done previously.

e 1 is negative and e 2 is positive: As in Algorithm 1, we have the following subcases:

e 1 is in a 1-cycle in G i +1 : In this case, e 1 becomes positive and e 2 becomes negative after the switch (see Proposition 7). Therefore, after the switch, we should delete e 1 from the MSF and add e 2 to the MSF. This can be done by cutting e 1 and then linking e 2 in the Link-Cut tree.

e 1 is not in a 1-cycle in G i +1 : In this case, e 1 stays negative and e 2 stays positive after the switch (see Proposition 7). The structure of the MSF does not change and we only need to update the weight of e 1 as done previously.

Remark 1. Updating the MSF for G can be done in O (log 4 m ) amortized time by directly utilizing the Dynamic-MSF data structure proposed by Holm et al. [16]. However, according to the cases described above, our update on the MSF is not ‘fully-dynamic’ because it only entails simple operations such as changing the weights by one unit for one or two edges and possibly switching two edges whose weights are consecutively ordered. Therefore, we could achieve an O (log m ) update in the worst case simply using the Link-Cut tree [20].

To see how to use the MSF to determine the connectivity of vertices in a ﬁltration, we ﬁrst rephrase Proposition 21 in the full version ∗ of [6] as follows:

Proposition 2. For a graph ﬁltration L : H 1   → H 2   → ···   → H s , assign a weight idx L ( e ) to each edge e in H := H s . For two vertices x,y that are connected in H , let π be the unique path connecting x,y in the unique minimum spanning forest of H and let w ∞ be the bottleneck weight of π . Then, the index of the ﬁrst graph in L where x,y are connected equals w ∞ + 1 .

For two vertices x,y in a graph ﬁltration L , checking whether x,y are connected in a graph H j in L boils down to ﬁnding the ﬁrst graph H j ∗ in L where x,y are connected, and then checking whether H j is before or after H j ∗ . This can be done in O (log m ) time by ﬁnding the bottleneck weight of the path connecting x,y in the MSF of H based on Proposition 2.

Time complexity. The costliest steps of Algorithm 1 are the operations on the DFT-Tree and Link-Cut tree. Hence, Algorithm 1 takes O (log m ) time in the worst case.

Preprocessing. In order to perform a sequence of updates on a given ﬁltration, we also need to construct the data structures maintained by Algorithm 1 for the initial ﬁltration. Constructing Π is nothing but computing standard persistence pairs on graphs, which takes O ( mα ( m )) time using Union-Find. Constructing T entails continuously performing the link operations on the DFT-Tree, which takes O ( m log m ) time. For constructing the MSF, we simply run the Kruskal’s algorithm, which can be done in O ( m log m ) time. Hence, the preprocessing takes O ( m log m ) time.

# 3.1.1 Justiﬁcation for vertex-vertex switch

Proposition 3. For the switch operation in Equation (2) where v 1 := σ and v 2 := τ are vertices ( v 1 ,v 2 are thus both positive), the pairings for F and F   change if and only if the following two conditions hold:

- 1. v 1 and v 2 are in the same tree in MF ( F ) ;
- 2. v 1 and v 2 are both unpaired when e is added in F , where e is the edge corresponding to the nearest common ancestor x of v 1 ,v 2 in MF ( F ) .


[Page 10]

# 4 Computing graph zigzag persistence

In this section, we show how the usage of the Link-Cut Tree [20], can improve the computation of graph zigzag persistence. For this purpose, we combine two recent results:

- • We show in [8] that a given zigzag ﬁltration can be converted into a standard ﬁltration for a fast computation of zigzag barcode.
- • Yan et al. [21] show that the extended persistence of a given graph ﬁltration can be computed by using operations only on trees.


Building on the work of [8], we ﬁrst convert a given simplex-wise graph zigzag ﬁltration into a cell -wise up-down ﬁltration, where all insertions occur before deletions. Then, using the extended persistence algorithm of Yan et al. [21] on the up-down ﬁltration with the Link-Cut Tree [20] data structure, we obtain an improved O ( m log m ) algorithm for computing graph zigzag persistence.

The algorithm, called FastZigzag [8], builds ﬁltrations on extensions of simplicial complexes called ∆ -complexes [15], whose building blocks are called cells or ∆ -cells . Notice that 1-dimensional ∆-complexes are nothing but graphs with parallel edges (also termed as multi-edges ) [8].

# 4.2 Extended persistence algorithm for graphs

Yan et al. [21] present an extended persistence algorithm for graphs in a neural network setting (see also [22]) which runs in quadratic time. We adapt it to computing up-down zigzag persistence while improving its time complexity with a Link-Cut tree [20] data structure.

Deﬁnition 12 indicates that for the up-down ﬁltration in Equation (4), Pers ∗ ( U ) can be considered as generated from the cell pairs similar to the simplex pairs in standard persistence [11]. Speciﬁcally, an interval [ b,d ] ∈ Pers ∗ ( U ) is generated from the pair (ˆ σ b − 1 , ˆ σ d ). While each cell appears twice in U (once added and once deleted), we notice that it should be clear from the context whether a cell in a pair refers to its addition or deletion. We then have the following:

Remark 2. Every vertex-edge pair for a closed-open interval in Pers 0 ( U ) comes from the ascending part U u of the ﬁltration U , and every edge-vertex pair for an open-closed interval in Pers 0 ( U ) comes from the descending part U d . These ascending and descending parts are as shown below:

$$
\mathcal { U } _ { u } \colon \varnothing & = \hat { G } _ { 0 } \hookrightarrow \hat { G } _ { 1 } \overset { \hat { \sigma } _ { 0 } } { \hookrightarrow } \dots \overset { \hat { \sigma } _ { 1 } } { \hookrightarrow } \hat { G } _ { k } , \\ \mathcal { U } _ { d } \colon \varnothing & = \hat { G } _ { m } \overset { \hat { \sigma } _ { m - 1 } } { \hookrightarrow } \hat { G } _ { m - 1 } \overset { \hat { \sigma } _ { m - 2 } } { \longleftrightarrow } \dots \overset { \hat { \sigma } _ { k } } { \longleftrightarrow } \hat { G } _ { k } .
$$

We ﬁrst run the standard persistence algorithm with the Union-Find data structure on U u and U d to obtain all pairs between vertices and edges in O ( k α ( k )) time, retrieving closed-open and open-closed intervals in Pers 0 ( U ). We also have the following:

Remark 3. Each closed-closed interval in Pers 0 ( U ) is given by pairing the ﬁrst vertex in U u , that comes from a connected component C of ˆ G k , and the ﬁrst vertex in U d coming from C . There is no extra computation necessary for this type of pairing.

Remark 4. Each closed-closed interval in Pers 1 ( U ) is given by an edge-edge pair in U , in which one edge is a positive edge from the ascending ﬁltration U u and the other is a positive edge from the descending ﬁltration U d .

To compute the edge-edge pairs, the algorithm scans U d and keeps track of whether an edge is positive or negative. For every positive edge e in U d , it ﬁnds the cycle c that is created the earliest in U u containing e and then pairs e with the youngest edge e   of c added in U u , which creates c in U u . To determine c and e   , we use the following procedure from [21]:

# Algorithm 3.

- 1. Maintain a spanning forest T of ˆ G k while processing U d . Initially, T consists of all vertices of ˆ G k and all negative edges in U d .
- 2. For every positive edge e in U d (in the order of the ﬁltration):


- (a) Add e to T and check the unique cycle c formed by e in T .
- (b) Determine the edge e   which is the youngest edge of c with respect to the ﬁltration U u . The edge e   has to be positive in U u .
- (c) Delete e   from T . This maintains T to be a tree all along.
- (d) Pair the positive edge e from U d with the positive edge e   from U u .


We propose to implement the above algorithm by maintaining T as a Link-Cut Tree [20], which is a dynamic data structure allowing the following operations in O (log N ) time ( N is the number of nodes in the trees): (i) insert or delete a node or an edge from the Link-Cut Trees; (ii) ﬁnd the maximum-weight edge on a path in the trees. Notice that for the edges in T , we let their weights equal to their indices in U u . ˆ

We build T by ﬁrst inserting all vertices of G k and all negative edges in U d into T in O ( m log m ) time. Then, for every positive edge e in U d , ﬁnd the maximum-weight edge   in the unique path in T connecting the two endpoints of e in O (log m ) time. Let e   be the edge in { e,  } whose index in U u is greater (i.e., e   is the younger one in U u ). Pair e   with e to form a closed-closed interval in Pers 1 ( U ). After this, delete e   from T and insert e into T , which takes O (log m ) time. Therefore, processing the entire ﬁltration U d and getting all closed-closed intervals in Pers 1 ( U ) takes O ( m log m ) time in total.

Finally, we convert Pers ∗ ( U ) to Pers ∗ ( F ) using the process in Theorem 13, which takes O ( m ) time. Therefore, computing Pers ∗ ( F ) takes O ( m log m ) time.

# 6 Discussion

We have designed O (log m ) update algorithms for switches in standard graph persistence. Also, we have designed an O ( m log m ) algorithm for computing zigzag persistence on graphs. It remains open if computing graph zigzag persistence can be further improved to run in O ( m log n ) time. Similarly, for updates in graph zigzag persistence, we have designed algorithms for all types of intervals. Among them, the updates for closed-closed intervals in dimension 1 and open-open intervals in dimension 0 take more than logarithmic time though still admitting a sub-linear algorithm ( O ( √ m log m )). It would be especially interesting to see if the O ( √ m log m ) complexity can be improved.

Furthermore, for all updates, we currently only considered switches, where the length of the ﬁltrations is always ﬁxed. How about those operations which change the length of the ﬁltration, e.g., ones that insert/delete some inclusion arrows into/from the ﬁltration? Can these operations be done in logarithmic time, or at least in sub-linear time?
