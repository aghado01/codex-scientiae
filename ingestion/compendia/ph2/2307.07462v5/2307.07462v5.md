# Abstract

Vines and vineyard connecting a stack of persistence diagrams have been introduced in the non-zigzag setting by Cohen-Steiner et al. [4]. We consider computing these vines over changing filtrations for zigzag persistence while incorporating two more operations: expansions and contractions in addition to the transpositions considered in the non-zigzag setting. Although expansions and contractions can be implemented in quadratic time in the non-zigzag case by utilizing the linear-time transpositions, it is not obvious how they can be carried out under the zigzag framework with the same complexity. While transpositions alone can be easily conducted in linear time using the recent FastZigzag algorithm [6], expansions and contractions pose difficulty in breaking the barrier of cubic complexity [7]. Our main result is that, the half-way constructed up-down filtration in the FastZigzag algorithm indeed can be used to achieve linear time complexity for transpositions and quadratic time complexity for expansions and contractions, matching the time complexity of all corresponding operations in the non-zigzag case.

# 1 Introduction

Computation of the persistence diagram (PD) also called the barcode from a given filtration has turned out to be a central task in topological data analysis (TDA). Such a filtration usually represents a nested sequence of sublevel sets of a function. In scenarios where the function changes, the filtration and hence the PD may also change. The authors in [4] provided an efficient algorithm for updating the PD over an atomic operation which transposes two consecutive simplex additions in the filtration. Using this atomic operation repeatedly, one can connect a series of filtrations derived from a time-varying function and obtain a stack of PD’s called the vineyard . The authors [4] show that updating the PD due to the atomic transposition can be computed in O ( m ) time if m simplices constitute the filtration. Recently, zigzag persistence [1, 2, 6, 8, 13, 14, 15] has drawn considerable attention in the community of topological data analysis. In this paper, we explore efficient updates of barcodes over such atomic operations for zigzag filtrations and include two additional types of operations [7] which are necessary for converting a zigzag filtration to any other: expansions that enlarge the filtration and contractions that shrink the filtration. Motivating examples are given in Appendix A of [7] and Section 3.1 of [17] for supporting these operations efficiently.

Although the work [4] introducing vineyard does not consider expanding and contracting a filtration, the two operations can be naturally defined in the non-zigzag setting. An expansion would involve inserting a simplex addition at a certain location in the non-zigzag filtration and a contraction would be its reverse. For implementing an expansion, one can attach a new simplex addition to the end of the current non-zigzag filtration and then bring it to the intended position by a series of transpositions [4]. For a contraction, one does the reverse. The cost of the update is then O ( m 2 ) because: (i) attaching a simplex addition to the filtration involves a reduction which takes O ( m 2 ) time; (ii) bringing it to correct position needs O ( m ) transpositions each consuming O ( m ) time. The main finding of this paper is that, although zigzag filtrations introduce more complications to the barcode computation, updating zigzag barcodes can be done with the same complexity as for the non-zigzag case over all the operations.

As recognized in [7], eight atomic operations are necessary for any zigzag filtration to transform to any other, including four implementing transpositions [1, 2, 8, 14, 15, 16] (henceforth called switches ) and another four implementing expansions [14, 15] and contractions. An immediate temptation would be to handle the updates by maintaining a non-zigzag filtration obtained from straightening the zigzag filtration using a recently proposed algorithm called FastZigzag [6]. Although we can easily implement the switches in linear time using this conversion [6] and the algorithm in [4], implementing the expansions and contractions in quadratic time becomes difficult. In fact, the authors of the arXiv paper [7] adopt this approach but cannot implement all operations due to an adjacency change observed for certain operations.

To see the challenge posed by the adjacency change, recall that the conversion to non-zigzag in [6] first goes through an (implicit) conversion to an up-down filtration [2], which is then converted to a non-zigzag one. Since the first part of the up-down filtration is the same as the first part of the final non-zigzag filtration, the adjacency change can be observed from the up-down filtration. In the constructed up-down filtration, the first part consists of all added simplices (with the same order) in the original zigzag filtration F . Consequently, the first part may contain multiple additions of the same simplex σ without any deletion in between [6]. These multiple additions of σ are distinguished by ∆ -cells [10, 12] which are copies of σ sharing boundaries non-trivially as in Figure 3. Also, one needs to consider two different types of expansions and contractions, where an expansion inserts two inclusion arrows involving the same simplex σ in a zigzag filtration, and a contraction as a reverse operation removes them (see Section 2.1 for formal definitions). Since the two inclusion arrows of σ being inserted or removed could either point toward or away from each other, we have inward and outward expansions along with the corresponding inward and outward contractions.

The outward expansions and contractions turn out to be harder than their inward counterparts. To see this, consider an outward expansion shown in Figure 1, where simplices added in the original zigzag filtrations and corresponding ∆ -cells added in the up-down filtrations are connected by dotted blue lines. Notice that there could be O ( m ) such changes. In [4], a transposition swaps only two consecutive columns and rows in the persistence boundary matrix [9] without any change on the simplices’ boundaries. The simplicity and locality of the transposition [4] make the linear algorithm possible. However, for the outward expansions and contractions, it is not at all clear that the change in adjacency arising in our case can be handled by a series of these transpositions [4]. A straightforward approach would be to perform the O ( m 2 ) reductions [9] on each changed column in the persistence boundary matrix. But then one may incur a cubic complexity to take care of the possible O ( m ) such changes. Notice that similar difficulty arises for outward contraction but not for inward expansion or contraction (see Figure 2).

In this paper, we find a way to tame down the curse of adjacency change by adopting primarily two ideas. First, to reduce the effect of the adjacency change in the outward expansions and contractions, we choose to work on up-down filtrations [2] instead. Up-down filtrations eliminate the further complication on the adjacency introduced by the 'coning' [3] of ∆ -cells which is the final step of the conversion in [6]. Second, we introduce a collapsing strategy for identifying boundaries which allows us to nullify the effect of adjacency changes on the time complexity. To explain intuitively the strategy, consider an outward contraction, where the adjacency change can be briefly stated as two p -cells σ 1 , σ 2 being identified as the same cell. Such a change can be enacted by introducing an extra ( p + 1) -cell χ whose boundary equals σ 1 + σ 2 and then collapsing χ (see Figure 5). Section 4 details the adjacency change and the algorithm. Another key advantage of working on up-down filtrations is that updates on up-down filtrations only need to maintain at most three chains per bar (see Remark 5), which is much less than the O ( m ) chains needed if working directly on the original zigzag filtrations [7].

# 2 Preliminaries

Since we utilize (partially) the conversion in [6], we work on ∆ -complexes [10, 12] instead of simplicial complexes in this paper. Building blocks of ∆ -complexes are called cells or ∆ -cells , which are similar to simplices but could have common faces in more relaxed ways (see Figure 3 and also Definition 1 of [6] for a precise definition). A zigzag filtration (or simply filtration ) is a sequence of ∆ -complexes

$$
\mathcal { F } \colon K _ { 0 } \leftrightarrow K _ { 1 } \leftrightarrow \cdots \leftrightarrow K _ { m } ,
$$

in which each K i ↔ K i +1 is either a forward inclusion K i   → K i +1 (an addition of several cells) or a backward inclusion K i ←   K i +1 (a deletion of several cells). Taking the p -th homology H p , we derive a zigzag module

$$
H _ { p } ( \mathcal { F } ) \colon H _ { p } ( K _ { 0 } ) \leftrightarrow H _ { p } ( K _ { 1 } ) \leftrightarrow \cdots \leftrightarrow H _ { p } ( K _ { m } ) .
$$

In H p ( F ) , each H p ( K i ) ↔ H p ( K i +1 ) is a linear map induced by inclusion. In this paper, we take the coefficient Z 2 for H p and hence chains or cycles can be treated as sets of cells. The zigzag module H p ( F ) has a decomposition [1, 11] of the form H p ( F ) ≃   k ∈ Λ I [ b k ,d k ] , in which each I [ b k ,d k ] is an interval module over the interval [ b k ,d k ] ⊆ { 0 , 1 ,...,m } . The (multi-)set of intervals Pers p ( F ) := { [ b k ,d k ] | k ∈ Λ } is an invariant of H p ( F ) and is called the p -th zigzag barcode (or simply barcode ) of F . Each interval in Pers p ( F ) is called a p -th persistence interval . We usually consider the homology H ∗ in all dimensions and take the zigzag module H ∗ ( F ) , for which we have Pers ∗ ( F ) =   p ≥ 0 Pers p ( F ) . In this paper, sometimes a filtration may have nonconsecutive indices on the complexes (i.e., some indices are skipped); notice that the barcode is still well-defined.

[Page 5]

An inclusion in a filtration is called cell-wise if it is an addition or deletion of a single cell σ , which we sometimes denote as, e.g., K i σ ←→ K i +1 . A filtration is called cell-wise if it contains only cell-wise inclusions. For computational purposes, filtrations in this paper are by default cell-wise filtrations starting and ending with empty complexes (as adopted in [6, 14]); notice that any filtration can be converted into this standard form by expanding the inclusions and attaching complexes to both ends.

# 3 Up-down conversion and easier updates

In this section, we first briefly overview the conversion to up-down filtrations in [6] and provide some definitions for up-down filtrations. We then describe how the conversion facilitates the updates for certain operations based on existing algorithms [8, 14]. For operations whose updates are more involved, we provide the algorithms in Section 4–6.

# 3.1 Conversion to up-down filtrations

Given a simplex -wise zigzag filtration

$$
\mathcal { F } \colon \varnothing = K _ { 0 } \leftarrow \overset { \sigma _ { 0 } } { \longrightarrow } K _ { 1 } \leftarrow \overset { \sigma _ { 1 } } { \longrightarrow } \cdots \longleftrightarrow K _ { m } = \varnothing
$$

consisting of simplicial complexes, we convert F into the following cell -wise up-down filtration consisting of ∆ -complexes [6]:

$$
\mathcal { U } \colon \varnothing = L _ { 0 } \overset { \xi _ { 0 } } { \longrightarrow } L _ { 1 } \overset { \xi _ { 1 } } { \longrightarrow } \dots \overset { \xi _ { n - 1 } } { \longrightarrow } L _ { n } \overset { \xi _ { n } } { \longrightarrow } L _ { n + 1 } \overset { \xi _ { n + 1 } } { \longrightarrow } \dots \overset { \xi _ { m - 1 } } { \longrightarrow } L _ { m } = \varnothing .
$$

Notice that an up-down filtration is a special type of zigzag filtration where the first half consists of only additions and the second half consists of only deletions [2]. In U , cells ξ 0 ,ξ 1 ,...,ξ n − 1 are distinct copies of simplices added in F with the addition order preserved (notice that the same simplex could be added more than once in F ). Symmetrically, cells ξ n ,ξ n +1 ,...,ξ m − 1 are distinct copies of simplices deleted in F , with the order also preserved. To build U from F , one only needs to list all the additions first and then the deletions in F , following their orders in F , with each addition of a simplex in F corresponding to a distinct ∆ -cell in U [6]. We have that the conversion from F to U can be done in O ( m ) time [6]. We also have m = 2 n because each added simplex must be eventually deleted in F . Figure 4 provides an example of the conversion, where an edge is added twice in F with σ 1 corresponding to its first addition and σ 2 corresponding to its second addition. In the up-down filtration U , σ 1 and σ 2 appear in the same complex forming parallel edges (also called multi-edges).

We then briefly describe how the intervals in Pers ∗ ( F ) and Pers ∗ ( U ) correspond. First notice that each interval in Pers ∗ ( F ) or Pers ∗ ( U ) can be considered as ‘generated’ by a pair of simplex-wise or cell-wise inclusions (i.e., simplex/cell additions or deletions). For example, an interval [ b,d ] ∈ Pers ∗ ( F ) is generated by the inclusion K b − 1 ↔ K b on the left and the inclusion K d ↔ K d +1 on the right. As indicated, there is a natural bijection ϕ from the cell-wise inclusions in U to the simplex-wise inclusions in F . For ease of presentation, we assign each simplex-wise inclusion K i σ i ←→ K i +1 in F the unique index i . We also similarly index cell-wise inclusions in U . We then let the domain and codomain of ϕ be the sets of indices for the simplex-wise or cell-wise inclusions. We have the following fact from [6]:

Theorem 1. There is a bijection from Pers ∗ ( U ) to Pers ∗ ( F ) s.t. corresponding intervals are generated by corresponding pairs of inclusions. Specifically, suppose that an interval in Pers ∗ ( U ) is generated by two cell-wise inclusions indexed at l and r ( l < r ). Then its corresponding interval in Pers ∗ ( F ) is generated by two simplex-wise inclusions indexed at ϕ ( l ) and ϕ ( r ) (notice that ϕ ( r ) may be less than ϕ ( l ) ). Therefore, in order to map an interval in Pers ∗ ( U ) back to the interval in Pers ∗ ( F ) , one only needs to look up the map ϕ which takes constant time.

Consider an up-down filtration U as built by the conversion in Section 3.1. Since each cell in U is added exactly once, we can uniquely denote each addition (resp. deletion) of a cell ξ in U as → ξ (resp. ← ξ ). We

Definition 2 (Creators of chains) . Let → ξ be an addition in U . A chain A is said to be created by → ξ if ξ ∈ A and all other cells in A are added before ξ in U . Moreover, Let ← ξ be a deletion in U . A chain A is said to be created by ← ξ if ξ ∈ A and all other cells in A are deleted after ξ in U . We also say that → ξ or ← ξ is the creator of A . When the direction of the arrow for ξ is clear in the context, we sometimes drop the arrow and simply say that A is created by ξ , or ξ is the creator of A .

Definition 3. We classify the pairs in Pers ∗ ( U ) and define their representatives respectively as follows:

- • A p -pair of the form ( → γ, → η ) is called closed-open . The representative for ( → γ, → η ) is a tuple of chains ( z,A ) with z = ∂ ( A ) , where z is a p -chain created by → γ and A is a ( p + 1) -chain created by → η .
- • A p -pair of the form ( ← γ, ← η ) is called open-closed . The representative for ( ← γ, ← η ) is a tuple of chains ( A,z ) with z = ∂ ( A ) , where A is a ( p + 1) -chain created by ← γ and z is a p -chain created by ← η .
- • A p -pair of the form ( → γ, ← η ) is called closed-closed . The representative for ( → γ, ← η ) is a tuple of chains ( z,A,z ′ ) with z + z ′ = ∂ ( A ) , where z is a p -chain created by → γ and z ′ is a p -chain created by ← η . Notice that A can contain any ( p + 1) -cells in U .


Remark 4. Representatives defined above are a special case of general zigzag representatives defined in [14]. For example, in a representative ( z,A,z ′ ) for a closed-closed pair, having z + z ′ = ∂ ( A ) ensures that [ z ] = [ z ′ ] in H ∗ ( L n ) , and the definition in [14] has similar requirements. Notice that we may have z = z ′ , for which A is simply empty.

Remark 5. To perform the update, we shall maintain a representative for each pair in the up-down filtration that we work on, which consists of at most three chains. This is only a slight difference from the two chains per bar maintained in [4], where one chain is from the ‘ R -matrix’ and another is from the ‘ V -matrix’.

We present below a fact helpful for the proof of correctness of algorithms in this paper:

Proposition 6. Let π be a set of pairs of additions and deletions in U s.t. each addition and deletion in U appears exactly once in π . If each pair in π admits a representative, then the pairs in π generate the intervals in Pers ∗ ( U ) .

Proof. First consider the first half U u of U containing only additions, which is indeed a non-zigzag filtration. We have that the representatives for the pairs in π induce an ‘ RU ’ decomposition for the persistence boundary matrix of U u . We also have similar facts for the second half U d of U containing only deletions. Then, for each pair ( ↔ ξ, ↔ ξ ′ ) in π , we have that ↔ ξ is positive and ↔ ξ ′ is negative based on the Pairing Uniqueness Lemma in [4]. The proposition then follows from Proposition 9 of [5].

# 3.3 Using conversion for easier updates

Utilizing the conversion in Section 3.1, our algorithms work on the corresponding up-down filtrations of F and F ′ for the operations in Section 2.1. Specifically, we maintain the barcode and representatives for the corresponding up-down filtration, and the barcode for the original zigzag filtration can be derived from the bijection ϕ as in Theorem 1. Notice that representatives for the pairs in the up-down filtration are essential for performing the update. Moreover, by Proposition 6, the correctness of our update algorithms follows from the correctness of the representatives that we maintain during the update operations. We briefly describe the ideas for the update in this section and provide full details in Appendix A.

Outward/inward switch. Since the switch in Equation (4) swaps two inclusions of different directions, the corresponding up-down filtrations before and after the switch are the same (see Section 3.1). So the time complexity for the update is O (1) .

Forward/backward switch. Corresponding to a forward (resp. backward) switch on the original zigzag filtration, there is a forward (resp. backward) switch in the up-down filtration [8]. To perform the update for forward/backward switches on up-down filtrations, we utilize the algorithm for the transposition diamond in [14], which takes O ( m ) time. Observe that the algorithm in [4] cannot be used on up-down filtrations.

Inward expansion. For the inward expansion from F ′ to F in Equation (5), assume that the up-down filtration U ′ corresponding to F ′ has the following m − 2 additions and deletions:

\mathcal { U } ^ { + } \colon \underbrace { \bullet \overset { \xi _ { 0 } } { \longrightarrow } \bullet \overset { \xi _ { 1 } } { \longrightarrow } \bullet \dots \underbrace { \bullet \overset { \xi _ { n - 2 } } { \longrightarrow } \bullet \overset { \hat { \sigma } } { \longrightarrow } \bullet \overset { \hat { \sigma } } { \longleftarrow } \bullet \overset { \xi _ { n - 1 } } { \longleftarrow } \bullet \overset { \xi _ { n } } { \longleftarrow } \bullet \dots \underbrace { \bullet \overset { \xi _ { m - 3 } } { \longleftarrow } \bullet } } _ { \infty } \bullet

To get the barcode and representatives for U + from those for U ′ , we utilize the algorithm for the injective and surjective diamond in [14], which takes O ( m 2 ) time. After this, we perform forward and backward switches on U + to place the two arrows ˆ σ   −→ and ˆ σ ←−   in appropriate positions to form U , which is the up-down filtration corresponding to F . Since no more than O ( m ) switches are performed, the switches in total takes O ( m 2 ) time. Therefore, the update for inward expansion takes O ( m 2 ) time. Notice that the above transition from U ′ to U + and from U + to U is valid because ˆ σ has no cofaces in U based on the conversion in [6].

Computing representatives for an initial up-down filtration. In order to perform a sequence of updates starting from an initial zigzag filtration, we need to compute the barcode and representatives for the initial up-down filtration. This can be done by adapting the algorithm in [14] which takes O ( m 3 ) time for an initial filtration of length m .

# 7 Conclusion

We have presented update algorithms for maintaining barcodes over a changing zigzag filtration. Two main questions come out of this research: (i) The representatives for the barcodes are maintained only in the up-down filtrations. An open question that remains is whether this can help maintain the representatives for the original zigzag filtration in quadratic time over all operations. (ii) Are there other interesting applications of the update algorithms presented in this paper? Their applications to computing vineyards for dynamic point clouds, multiparameter persistence, and dynamic network are mentioned in [7, 17]. We hope that there are other dynamic settings which can benefit from efficient zigzag updates.

# A.2 Inward expansion

We only provide details for performing the update from U ′ to U + . Since an inward expansion takes place from U ′ to U + , we notice that the interval mapping for an inward expansion is described by theorems for the injective and surjective diamond in [14] (Theorem 2.2, 2.3). An injective (resp. surjective) diamond is indeed an inward expansion where the induced map H ∗ ( K i − 1 ) → H ∗ ( K i ) in Equation (5) is injective (resp. surjective). We can then utilize the algorithm for the injective and surjective diamond in [14] (Algorithm 4 and 5) for computing the update from U ′ to U + . Notice that Algorithm 4 and 5 in [14] have the same assumption on an input zigzag filtration as the algorithm for the transposition diamond [14] mentioned above, i.e., the first part of the zigzag filtration contains additions or deletions but the second part contains only deletions. The time complexity for performing the update is O ( m 2 ) [14].

# A.3 Computing representatives for an initial up-down filtration

The algorithm presented in [14] can be considered as a process which iteratively maintains the barcode and representatives for a partial zigzag filtration derived from the input zigzag filtration. In each iteration of the algorithm [14], the partial zigzag filtration grows and eventually becomes the complete input filtration. The algorithm maintains the barcode and representatives by taking summations of the intervals and their representatives in each iteration. Notice that the algorithm achieves the claimed complexity (which is O ( m 3 ) for an up-down filtration of length m ) because it does not maintain the full representative for an interval (which could contain O ( m ′ ) cycles for a general zigzag filtration of length m ′ ). Instead, the algorithm maintains a representative cycle at a single index so that summing the representative cycles of two intervals takes O ( m ) time (because each cycle contains O ( m ) cells). Since we are working on up-down filtrations in this paper, we can modify the algorithm in [14] so that whenever we sum two intervals in the algorithm, we also sum the full representatives (as in Definition 3) for the two intervals. Since a full representative in an up-down filtration contains at most three cycles/chains (see Definition 3), the time complexity for computing representatives for an initial up-down filtration is still O ( m 3 ) .
