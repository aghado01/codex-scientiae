# End-to-End Document Repair Pipeline

You are an automated document repair agent. Your task is to convert raw Docling Markdown exports into `codex-scientiae` compliant Markdown by leveraging the raw Python extraction scripts and the JSON sidecar artifacts.

Execute the workflow sequentially

### Prerequisites: Python, Helper scripts, Layout

1. There is a locally installed repo `.venv` for python executable and utilize the venv for running python scripts.

2. Python helper scripts mentioned below are found under `scripts/`:

   scripts\reconstruct_tables.py
   scripts\math_enrichment.py

3. Workflow items located under `ingestion/` with directory path structure parallel to the `codex-scientiae` end points themselves e.g. `ingestion/compendia/clustering` mirrors `compendia/clustering` with the exception of where the final markdown files will land after ingestion processing is approved.

### Phase 1: Artifact Generation (Tool Execution)

1. **Generate Tables:** Execute `python table_reconstruction.py <document.json>`. Save the exact console output to a temporary workspace file named `temp_tables.md`.
2. **Generate Math Prose:** Execute `python math_enrichment.py <document.json>`. Save the exact console output to a temporary workspace file named `temp_math.md`.

   The math artifact is organized by page: each section begins with `[Page N]` matching the `[Page N]` boundary markers in the source markdown. Within each page, `$$...$$` blocks are display equations extracted from `"type": "formula"` nodes in the JSON (Docling's structured extraction, generally cleaner than the OCR markdown). Inline `$...$` wrapping applies only to PDFs where Docling recorded math-font metadata on text spans; if no inline wrapping appears, that PDF lacks font metadata and inline math must be identified manually from the raw markdown.

### Phase 2: Markdown Injection (Semantic Repair)

Open the original `<document.md>` file and begin the semantic repair using the artifacts you just generated.

1. **Table Injection:** Locate the broken, flattened text tables in `<document.md>`. Delete them entirely and paste the perfectly formatted Markdown pipe tables from `temp_tables.md` in their place.
2. **Display Math Repair:** Navigate `temp_math.md` page by page alongside the corresponding `[Page N]` section of `<document.md>`. For each `$$...$$` block in the artifact, locate the matching raw equation in the markdown (usually a `$$...$$` block with OCR noise) and replace it with the cleaner artifact version, adding `\tag{X}` for numbered equations.
3. **Inline Math Enrichment:** If the artifact contains `$...$` wrapped spans (font-metadata PDFs), use them as a map to find and wrap missing inline math in the prose. For PDFs without font metadata, identify inline math manually from context and OCR conventions.
4. **Block Math Reconstruction:** For equations where both the artifact and raw markdown are garbled, reconstruct from mathematical context using `$$...$$` and `\tag{X}` as defined in `STANDARDS.md`.

### Phase 3: Prose Hygiene (The Polish)

Run through the document one last time and apply the rules from `CHECKLIST.md`:

1. **Line-Breaks:** Remove arbitrary hard wraps (`\n`) within paragraphs.
2. **Ligatures:** Replace OCR ligatures (e.g., `fi`, `fl`, `ffi`) with standard ASCII characters.
3. **Duplicates:** Delete duplicated image captions or redundant prose blocks generated by the OCR.

Once Phase 3 is complete, save the file and terminate the process.

### Phase 4: Trim the fat

Remove irrelevant sections including acknowledgements, grant/funding statements, declarations regarding conflicting interests
